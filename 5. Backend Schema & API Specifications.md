Backend Schema & API Specifications
Esquema de Base de Datos y Definición de Contratos API - Beneficios Alimenticios Institucionales

Este documento técnico define la arquitectura de datos relacional y los contratos de API RESTful para la plataforma de distribución de bolsas de víveres y combos proteicos a trabajadores y jubilados del sector público. El diseño integra mecanismos de seguridad asimétrica FIDO2/WebAuthn, soporte para tarjetas de proximidad NFC, auditoría estricta de excepciones y un motor de sincronización offline con garantía de idempotencia absoluta.

--------------------------------------------------------------------------------
1. Esquema de Base de Datos Relacional (PostgreSQL / SQLite Replicado)
El backend utiliza el modelo relacional implementado en schema_combos_passkeys.sql, adaptado para la gestión integral de nóminas ministeriales y operativos de bienestar social:

- departments: Direcciones Generales y dependencias ministeriales (id, name, code, created_at).
- workers: Padrón unificado de beneficiarios institucionales.
  - id (UUID PK)
  - document_id (VARCHAR(20) UNIQUE) -- Cédula de Identidad venezolana (V- / E-)
  - full_name (VARCHAR(150))
  - email (VARCHAR(100) UNIQUE NULL)
  - department_id (UUID FK -> departments)
  - status (ENUM: 'active', 'suspended', 'terminated')
  - worker_type (ENUM: 'activo', 'jubilado', 'pensionado', 'contratado')
  - has_smartphone (BOOLEAN DEFAULT TRUE)
  - contingency_reason (VARCHAR(100) NULL) -- 'adulto_mayor_sin_smartphone', 'device_lost', 'discapacidad'
  - created_at, updated_at
- passkey_credentials: Llaves públicas FIDO2/WebAuthn vinculadas al chip seguro del teléfono de los beneficiarios.
  - id (UUID PK), worker_id (FK), credential_id (TEXT UNIQUE), public_key (TEXT PEM/COSE), sign_count (BIGINT), device_name (VARCHAR(100)), transports (TEXT[]).
- nfc_cards: Registro de tarjetas físicas de proximidad asignadas a personal jubilado o en contingencia.
  - id (UUID PK), worker_id (FK), card_uid (VARCHAR(100) UNIQUE), status (ENUM: 'active', 'revoked', 'lost'), issued_at (TIMESTAMP).
- combos: Catálogo de rubros y paquetes de alimentos institucionales.
  - id (UUID PK), name (VARCHAR(100)), description (TEXT)
  - category (ENUM: 'bolsa_viveres', 'combo_proteico', 'combo_navideno', 'combo_especial')
  - is_active (BOOLEAN DEFAULT TRUE)
- daily_entitlements: Asignaciones de combos por jornada de entrega para cada trabajador/jubilado.
  - id (UUID PK), worker_id (FK), combo_id (FK), valid_date (DATE), shift (ENUM: 'mañana', 'tarde', 'noche' o jornada única), status (ENUM: 'pending', 'claimed', 'expired').
- distribution_points: Puntos de despacho físico en sedes ministeriales y regionales.
  - id (UUID PK), name (VARCHAR(100) - Ej: 'Sede Principal - Almacén Sótano 1', 'Sede Regional Centro'), location_code (VARCHAR(50) UNIQUE).
- deliveries: Registro inalterable de cada bolsa o combo entregado.
  - id (UUIDv4 PK generado en cliente)
  - entitlement_id (UUID FK -> daily_entitlements)
  - worker_id (UUID FK -> workers)
  - distribution_point_id (UUID FK -> distribution_points)
  - delivered_by_user_id (UUID FK -> operador de almacén)
  - verification_method (ENUM: 'passkey_qr', 'nfc_card', 'supervisor_override')
  - signature_proof (TEXT NULL - obligatorio cuando verification_method = 'passkey_qr')
  - challenge_nonce (VARCHAR(64) NULL)
  - supervisor_id (UUID FK NULL - obligatorio si verification_method = 'supervisor_override')
  - override_reason (VARCHAR(255) NULL - justificación de entrega manual/jubilado sin smartphone)
  - is_offline_sync (BOOLEAN DEFAULT FALSE)
  - delivered_at (TIMESTAMP WITH TIME ZONE)
  - synced_at (TIMESTAMP WITH TIME ZONE)

Restricción Anti-Fraude e Idempotencia Estricta:
CREATE UNIQUE INDEX idx_unique_daily_claim ON deliveries (worker_id, entitlement_id);
Garantiza que ningún funcionario o jubilado pueda retirar dos veces el mismo derecho de víveres o proteínas asignado en una jornada.
