Backend Schema & API Specifications
Esquema de Base de Datos y Definición de Contratos API - Beneficios Alimenticios Institucionales
Versión: 2.0 (Soporte B2G, Multi-Ente, Campañas, Auditoría de Toneladas y Respaldo Preventivo)

Este documento técnico define la arquitectura de datos relacional y los contratos de API RESTful para la plataforma de distribución de beneficios alimenticios institucionales (bolsas de víveres secos, combos proteicos, útiles escolares y combos navideños) a trabajadores activos y jubilados del sector público. El diseño integra mecanismos de seguridad asimétrica FIDO2/WebAuthn, soporte para tarjetas de proximidad NFC, auditoría de excepciones, parametrización institucional (branding B2G), asistente de activación de 5 pasos, cálculo logístico de toneladas y un motor de sincronización offline con garantía de idempotencia absoluta.

--------------------------------------------------------------------------------
1. Esquema de Base de Datos Relacional (PostgreSQL / SQLite)
El backend utiliza el modelo relacional implementado en `schema_combos_passkeys.sql` y administrado dinámicamente en `backend/db.js`:

- tenant_settings: Configuración y personalización institucional del organismo (B2G Multi-Ente).
  - id (VARCHAR(50) PRIMARY KEY DEFAULT 'current_tenant')
  - entity_name (VARCHAR(150)) -- Nombre oficial del organismo
  - entity_short_name (VARCHAR(50)) -- Siglas (ej: MIPPCI)
  - logo_url (TEXT) -- Ruta o data URI en base64 del logotipo
  - primary_color (VARCHAR(20)) -- Color hex primario de marca (#1e40af)
  - secondary_color (VARCHAR(20)) -- Color hex secundario (#3b82f6)
  - validation_mode (VARCHAR(20) DEFAULT 'strict_passkey')
  - is_initialized (INTEGER DEFAULT 0) -- Bandera de estado del Wizard
  - is_demo_mode (INTEGER DEFAULT 1) -- Modo demostrativo o producción
  - created_at, updated_at

- departments: Direcciones Generales y dependencias ministeriales.
  - id (UUID PK), name (VARCHAR(150)), code (VARCHAR(50)), created_at.

- workers: Padrón unificado de beneficiarios institucionales.
  - id (UUID PK)
  - document_id (VARCHAR(20) UNIQUE) -- Cédula de Identidad (V- / E-)
  - full_name (VARCHAR(150))
  - email (VARCHAR(100) UNIQUE NULL)
  - department_id (UUID FK -> departments)
  - status (VARCHAR(20) DEFAULT 'active') -- active, suspended, terminated
  - worker_type (VARCHAR(20)) -- activo, jubilado, pensionado, contratado
  - role (VARCHAR(20) DEFAULT 'beneficiary') -- beneficiary, operator, supervisor, director, admin
  - has_smartphone (INTEGER/BOOLEAN DEFAULT 1)
  - contingency_reason (VARCHAR(100) NULL) -- adulto_mayor_sin_smartphone, device_lost
  - password_hash (VARCHAR(255) NULL) -- Credencial para roles administrativos
  - created_at, updated_at

- passkey_credentials: Llaves públicas FIDO2/WebAuthn en hardware seguro.
  - id (UUID PK), worker_id (FK), credential_id (TEXT UNIQUE), public_key (TEXT PEM/COSE), sign_count (BIGINT), device_name (VARCHAR(100)), transports (TEXT[]).

- nfc_cards: Registro de tarjetas físicas de proximidad para contingencia.
  - id (UUID PK), worker_id (FK), card_uid (VARCHAR(100) UNIQUE), status (VARCHAR(20)), issued_at (TIMESTAMP).

- combos: Catálogo de paquetes y beneficios alimenticios.
  - id (UUID PK), name (VARCHAR(100)), description (TEXT)
  - category (VARCHAR(50)) -- bolsa_viveres, combo_proteico, utiles_escolares, combo_higienico, combo_navideno
  - calories (INTEGER DEFAULT 0)
  - dietary_info (TEXT)
  - weight_kg (DECIMAL(10,2) DEFAULT 12.50) -- Peso bruto para cálculo de toneladas métricas
  - is_active (INTEGER DEFAULT 1)

- campaigns: Jornadas y operativos institucionales planificados.
  - id (UUID PK), name (VARCHAR(150)), start_date (DATE), end_date (DATE)
  - status (VARCHAR(20) DEFAULT 'active') -- draft, active, closed
  - description (TEXT), created_at (TIMESTAMP)

- campaign_distribution_points: Asociación M:N de sedes por jornada.
  - campaign_id (UUID FK), distribution_point_id (UUID FK)

- campaign_combos: Asociación M:N de tipos de combos habilitados por campaña.
  - campaign_id (UUID FK), combo_id (UUID FK)

- distribution_points: Puntos de despacho físico en sedes ministeriales.
  - id (UUID PK), name (VARCHAR(100)), location_code (VARCHAR(50) UNIQUE), address (TEXT), is_active (INTEGER DEFAULT 1).

- daily_entitlements: Asignaciones de combos por jornada y trabajador.
  - id (UUID PK), worker_id (FK), combo_id (FK), campaign_id (FK NULL), valid_date (DATE), shift (VARCHAR(20)), status (VARCHAR(20) DEFAULT 'pending').

- deliveries: Registro inalterable de entregas despachadas.
  - id (UUID PK)
  - entitlement_id (UUID FK -> daily_entitlements)
  - worker_id (UUID FK -> workers)
  - distribution_point_id (UUID FK -> distribution_points)
  - delivered_by_user_id (UUID FK)
  - verification_method (VARCHAR(30)) -- passkey_qr, nfc_card, supervisor_override
  - signature_proof (TEXT NULL)
  - challenge_nonce (VARCHAR(64) NULL)
  - supervisor_id (UUID FK NULL)
  - override_reason (VARCHAR(255) NULL)
  - is_offline_sync (INTEGER/BOOLEAN DEFAULT 0)
  - delivered_at (TIMESTAMP), synced_at (TIMESTAMP)

- notifications: Centro de avisos y notificaciones internas.
  - id (UUID PK), title (VARCHAR(150)), message (TEXT), target_role (VARCHAR(50)), is_read (INTEGER DEFAULT 0), created_at (TIMESTAMP).

Restricción Anti-Fraude e Idempotencia Estricta:
CREATE UNIQUE INDEX idx_unique_daily_claim ON deliveries (worker_id, entitlement_id);

2. Contratos de APIs RESTful

2.1 Diagnóstico de Sistema y Asistente de Activación
- GET /api/v1/system/status:
  Retorna estado del servidor, motor de base de datos activo (sqlite_local vs supabase_cloud), flags `is_initialized`, `is_demo_mode`, `has_admin` e información del ente.
- POST /api/v1/setup/initialize:
  Ejecuta la configuración inicial del Asistente de 5 Pasos:
  Payload: `{ "entity_name": "MIPPCI", "entity_short_name": "MIPPCI", "primary_color": "#1e40af", "admin_document_id": "V-12345678", "admin_name": "Director General", "admin_email": "rrhh@mippci.gob.ve", "admin_password": "...", "campaign_name": "Jornada Noviembre 2026" }`
- POST /api/v1/system/demo-mode:
  Alterna entre modo demostrativo y modo productivo estricto.

2.2 Gobernanza, Respaldo Preventivo y Puesta a Cero
- GET /api/v1/admin/export-backup:
  Genera y descarga el archivo `backup_bolsa_institucional_{timestamp}.json` conteniendo todas las tablas del sistema para auditoría y archivo histórico.
- POST /api/v1/admin/factory-reset:
  Requiere confirmación explícita `{ "confirm_reset": true }`. Limpia las tablas operativas de beneficiarios, entregas y asignaciones manteniendo la estructura relacional.

2.3 Gestión de Identidad y Marca (Branding Multi-Ente)
- GET /api/v1/tenant/settings: Retorna configuración visual y parámetros operativos.
- POST /api/v1/tenant/settings: Actualiza nombre, siglas, colores corporativos y logotipo en Base64/SVG.
- POST /api/v1/tenant/settings/validation-mode: Alterna modo de validación (`strict_passkey` vs `flexible_contingency`).

2.4 Ingesta de Nómina y Padrón
- GET /api/v1/payroll/sample-payroll.csv: Descarga la plantilla CSV oficial estandarizada.
- POST /api/v1/payroll/batch-import:
  Carga masiva con parseo de CSV o arreglo JSON de beneficiarios con validación de cédulas.
- POST /api/v1/admin/workers: Alta manual de un funcionario o jubilado.
- PUT /api/v1/admin/workers/:id: Actualización de datos o reasignación de departamento.
- DELETE /api/v1/admin/workers/:id: Baja lógica o retiro de nómina.

2.5 Campañas y Puntos de Distribución Inline
- GET /api/v1/admin/campaigns: Lista de jornadas con estadísticas de avance.
- POST /api/v1/admin/campaigns: Creación de nueva campaña vinculando combos y sedes.
- PUT /api/v1/admin/campaigns/:id/status: Cambio de estado (active, closed).
- POST /api/v1/admin/campaigns/:id/notify: Emite notificación a los beneficiarios de la jornada.
- GET /api/v1/distribution-points: Listado de puntos físicos de entrega.
- POST /api/v1/distribution-points: Creación inline de nuevo almacén o mesa de despacho.
- PUT /api/v1/distribution-points/:id: Modificación de punto de entrega.

2.6 Criptografía FIDO2, Passkeys y QR
- POST /api/v1/auth/passkey/register-challenge: Emite desafío aleatorio de 32 bytes para registro.
- POST /api/v1/auth/passkey/register-verify: Registra la clave pública ECDSA P-256 en base de datos.
- POST /api/v1/auth/passkey/sign-offline: Genera prueba de firma para terminales sin hardware seguro.
- POST /api/v1/verify/qr: Validación directa de payload QR estándar RFC por el backend.

2.7 Sincronización Offline e Idempotencia
- GET /api/v1/sync/daily-pack?distribution_point_id={uuid}&date={yyyy-mm-dd}:
  Descarga el paquete integral para operar desconectado en almacén.
- POST /api/v1/sync/batch-deliveries:
  Recepciona el lote de entregas acumuladas offline e inserta bajo `idx_unique_daily_claim`.

2.8 Auditoría Avanzada y Estadísticas de Toneladas
- GET /api/v1/admin/audit/stats:
  Retorna métricas de impacto: total de combos reclamados, desglose por método de verificación, auditoría de excepciones por supervisor y cálculo matemático en toneladas métricas (`total_metric_tons_food`, `total_metric_tons_protein`).
- GET /api/v1/admin/export: Descarga en Excel/CSV de la bitácora consolidada de entregas.
