Documento de Requisitos Técnicos (TRD)
Arquitectura y Especificación Técnica del Sistema
Versión: 2.0 (Arquitectura Híbrida On-Premise / Serverless Resiliente B2G)

Este documento técnico describe la estructura de un sistema distribuido que prioriza el funcionamiento sin conexión a internet (Offline-First), diseñado para operar de manera segura y eficiente mediante tres componentes principales: una Progressive Web App (PWA) de autoservicio para trabajadores beneficiarios, una aplicación de mesa de despacho para distribuidores con motor de base de datos local y escáner multi-cámara, y un Servidor Central RESTful con capacidad dual de ejecución (On-Premise con motor nativo de alto rendimiento o Serverless Cloud resiliente con WebAssembly).

--------------------------------------------------------------------------------
1. Arquitectura General del Sistema y Pila Tecnológica
El sistema implementa una arquitectura desacoplada y resiliente:

1.1 Cliente Frontend / PWA (Trabajador, Distribuidor y Portal de Gobernanza):
- PWA Unificada (HTML5, Vanilla CSS responsivo, JavaScript ES6+ sin frameworks pesados).
- Service Worker (`public/sw.js`) con estrategia Cache-First para recursos estáticos y gestión de conectividad online/offline.
- Motor de Criptografía de Cliente: Web Cryptography API (`crypto.subtle`) y WebAuthn API (`navigator.credentials`) para autenticación biométrica y firma asimétrica en hardware seguro (Secure Enclave / Android StrongBox).
- Módulo de Escaneo y Captura Visual: Motor `html5-qrcode` integrado con selector dinámico de cámaras (`Html5Qrcode.getCameras()`), permitiendo conmutar entre cámara trasera (environment), cámara frontal (user) o lentes auxiliares gran angular.
- Generador de Códigos QR: Biblioteca `qrcode.bundle.js` con soporte para renderizado en Canvas / SVG según especificaciones estándar RFC con corrección de errores nivel M.

1.2 Backend Central & API Gateway:
- Runtime: Node.js 20.x / 22.x LTS.
- Servidor HTTP: Express.js 5.x con soporte de streaming y payloads de nómina de hasta 50MB.
- Autenticación y Criptografía de Servidor: Algoritmo ECDSA sobre curva P-256 (secp256r1 / ES256) y HMAC-SHA256 para webhooks de nómina.

1.3 Capa de Datos Híbrida y Resiliente (Dual Engine):
- Entorno de Producción On-Premise / VPS Dedicado: Motor nativo `better-sqlite3` con precompilación de sentencias SQL en memoria y soporte de réplica o migración directa a PostgreSQL 15+ (`pg`).
- Entorno Serverless / Cloud (Vercel): Motor WebAssembly resiliente (`sql.js` compilado C/C++ a WASM) que elimina dependencias binarias externas en lambdas efímeras, con sincronización opcional hacia Supabase REST (`@supabase/supabase-js`).
- Mecanismo de Migración y Dump: Script automatizado `generate_sql_dump.js` que extrae esquemas y datos idénticos para SQLite (`dump_sqlite_produccion.sql`) y PostgreSQL (`dump_postgresql_produccion.sql`).

1.4 Arquitectura Modular y Desacoplamiento (Release v2.5):
- Backend: Separación estricta de responsabilidades en `backend/controllers/` (lógica de negocio), `backend/routes/` (definición de endpoints RESTful bajo `/api/v1/`) y `backend/middleware/` (gestión de errores y validación de esquemas). El archivo `backend/server.js` actúa como bootstrap minimalista de 67 líneas.
- Frontend Core: Capa fundamental en `public/js/core/` que provee el Event Bus reactivo (`state.js`), cliente de transporte HTTP unificado (`api.js`), avisos flotantes no bloqueantes (`toast.js`), síntesis acústica (`audio.js`) y cargador dinámico de plantillas (`templates.js`).
- Frontend Módulos: Funcionalidades desacopladas en `public/js/modules/` (`auth.js`, `beneficiary.js`, `distributor.js`, `admin.js`, `combos.js`, `payroll.js`, `share.js`, `settings.js`, `notifications.js`).
- Plantillas HTML: Desacoplamiento de modales en `public/templates/modals.html` para reducir el tamaño inicial del DOM en más de un 34% y garantizar carga bajo demanda.

2. Especificación de Passkeys y Criptografía Asimétrica
- Estándar: FIDO2 / WebAuthn (Public Key Cryptography).
- Algoritmo de Firma: ECDSA P-256 (SHA-256 with ECDSA, `ES256` / `secp256r1`).
- Aislamiento de Llave Privada: Hardware dedicado (Apple Secure Enclave, Android Keystore / StrongBox). La llave privada nunca es exportable ni visible por el software o la red.
- Desafío (Challenge): Nonce criptográfico aleatorio de 32 bytes (256 bits) de un solo uso para prevenir ataques de repetición (replay attacks).

Estructura del Payload QR Firmado (RFC):
```json
{
  "wid": "UUID_TRABAJADOR",
  "ent": "UUID_ENTITLEMENT",
  "ts": 1729022400,
  "nonce": "NONCE_32_BYTES_HEX",
  "sig": "FIRMA_ECDSA_P256_BASE64URL"
}
```

3. Estrategia de Sincronización Offline-First
- Descarga del Paquete de Jornada (`GET /api/v1/sync/daily-pack`):
  Al iniciar la jornada en el almacén o mesa de despacho, el terminal descarga el padrón completo de beneficiarios habilitados, el catálogo de llaves públicas FIDO2 asociadas y los derechos vigentes (`daily_entitlements`).
- Verificación Criptográfica Local Autónoma:
  El escáner del distribuidor lee el código QR, verifica la vigencia del timestamp (máximo 60 segundos), comprueba el desafío y valida la firma digital contra la llave pública almacenada en la base de datos local SQLite, sin cursar ninguna petición HTTP.
- Idempotencia Estricta y Despacho en Lote (`POST /api/v1/sync/batch-deliveries`):
  Cada entrega completada genera un identificador UUIDv4 único en el cliente. Al restablecerse el enlace de red, las entregas se envían en bloque al servidor central.
  En base de datos, la restricción de integridad `CREATE UNIQUE INDEX idx_unique_daily_claim ON deliveries (worker_id, entitlement_id);` garantiza a nivel relacional que ningún derecho sea liquidado más de una vez, descartando duplicados sin alterar las transacciones legítimas.

4. Gobernanza del Sistema, Puesta a Cero y Respaldo Preventivo
- Snapshot Preventivo Mandatorio (`GET /api/v1/admin/export-backup`):
  Previo a cualquier operación destructiva o de reinicio de base de datos, el sistema genera y descarga un paquete estructurado JSON con metadatos institucionales, configuración del ente, padrón de trabajadores, credenciales, historial inalterable de entregas y auditorías.
- Puesta a Cero (Factory Reset Seguro) (`POST /api/v1/admin/factory-reset`):
  Limpia las tablas operativas garantizando el aislamiento de pruebas y permitiendo la activación de un nuevo ciclo ministerial con el Asistente de 5 Pasos.
- Asistente de Activación (`POST /api/v1/setup/initialize`):
  Configura dinámicamente el `tenant_settings` (nombre institucional, color primario, logo) y promueve la cuenta del Director de Gestión Humana.

--------------------------------------------------------------------------------
5. Seguridad, Cumplimiento y Rendimiento
- Cifrado en Tránsito: TLS 1.3 / HTTPS obligatorio para permitir el uso de WebAuthn y APIs de cámara web en navegadores modernos.
- Latencia de Verificación Local: Validación de firma ECDSA y verificación de elegibilidad en SQLite local < 45 ms por beneficiario.
- Protección de Carga de Archivos: Límite de 50MB en peticiones de nómina con captura de `rawBody` para validación de firma HMAC SHA-256.
- Accesibilidad Operativa: Interfaz adaptativa con modo de Alto Contraste para terminales industriales y almacenes con luz solar o condiciones de visibilidad adversas.
