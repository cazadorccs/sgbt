Este documento establece un plan de respaldo operativo para asegurar que todos los empleados reciban sus beneficios alimentarios incluso cuando ocurran problemas tecnológicos, como la falta de un teléfono inteligente, fallas mecánicas en los dispositivos o ausencia de datos biométricos. Para lograrlo, introduce métodos alternativos de validación, permitiendo el uso de tarjetas físicas NFC o RFID vinculadas al perfil del usuario, así como un sistema de autorización manual gestionado por supervisores mediante credenciales especiales. Finalmente, todo este esquema se integra a nivel técnico actualizando la base de datos con nuevos campos y registros de trazabilidad, lo que garantiza un control transparente y auditable de cada entrega realizada bajo circunstancias imprevistas.

Especificación de Flujos de Contingencia (Anexo a PRD y Esquema de BD)
1. Justificación y Alcance
Para garantizar que el 100% de los trabajadores reciban sus combos alimenticios en tiempo y forma, la plataforma soporta alternativas operativas ante tres escenarios no ideales:
Trabajadores sin teléfono inteligente o con teléfono no compatible.
Pérdida, robo, olvido o descarga de batería del celular.
Trabajadores sin biometría configurada en el sistema operativo.
--------------------------------------------------------------------------------
2. Requisitos de Producto (Adición al PRD)
FR-CONT-01: Validación por Tarjetas NFC / RFID
El sistema permitirá vincular una tarjeta NFC o RFID física al perfil del trabajador (worker_id).
En el punto de entrega, el distribuidor podrá escanear la tarjeta física en lugar del QR firmado con Passkey.
La entrega por NFC se validará contra la base de datos local (SQLite) del distribuidor para verificar el derecho del día.
FR-CONT-02: Liberación Manual Supervisada (Supervisor Override)
La aplicación del distribuidor incluirá un módulo de búsqueda manual por número de documento / cédula.
Si un trabajador no tiene smartphone ni tarjeta NFC, un supervisor autorizado podrá ingresar su PIN/Biometría de operador y seleccionar un motivo de anulación (override_reason) para liberar el combo.
Se registrará el supervisor_id obligatorio para auditorías internas.
FR-CONT-03: Trazabilidad de Métodos de Validación
Cada transacción registrará explícitamente el método utilizado: 'passkey_qr', 'nfc_card' o 'supervisor_override'.
--------------------------------------------------------------------------------
3. Extensión del Esquema de Base de Datos (Adición al Schema Backend)
A. Nuevos Campos en la Tabla workers
has_smartphone (BOOLEAN DEFAULT TRUE): Indica si el beneficiario opera mediante App móvil.
contingency_reason (VARCHAR(100)): Razón del modo contingencia (ej: 'no_smartphone', 'device_lost', 'disability').
B. Nueva Tabla nfc_cards
id (UUID PK)
worker_id (UUID FK UNIQUE -> workers(id))
card_uid (VARCHAR(100) UNIQUE NOT NULL): UID grabado en el chip NFC de la tarjeta.
status (ENUM: 'active', 'revoked', 'lost')
issued_at (TIMESTAMP)
C. Modificaciones en la Tabla deliveries
verification_method (ENUM: 'passkey_qr', 'nfc_card', 'supervisor_override')
supervisor_id (UUID FK -> workers(id)): Requerido en liberaciones manuales.
override_reason (VARCHAR(255)): Justificación de la entrega manual.
signature_proof (TEXT NULL): Opcional si la entrega no fue firmada por Passkey.
